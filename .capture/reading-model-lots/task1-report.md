# Task 1: persistent final read views

Implemented bounded namespace/date/signature typed views in the existing disposable projection SQLite file. V8 serialization preserves Maps, insertion/property order and undefined; SHA-256 detects changed blobs. Generic views share retained-byte admission, eviction, physical page cap and discard with raw periods and Home views. Each generic namespace/date retains one signature and there are at most 32 generic rows.

Collector final closed-day summaries now persist through both daySummary (Reports) and viewedDaySummary (Review). They reuse persistedHomeKey's complete dependencies, validate again before storing, and discard stale raw memos on a changed persisted key. Counter reports are freshly evaluated for each signature, so active ends, lease expiry and clock rollback cannot validate a frozen result.

Closed billing snapshots cache only billingEvidence:true, persistedOnly:true, countTaskCounters:false reads. Their key includes exact bounds/chunks/options, source inode identity, pinned durable projection identity/revision, global evidence count/max timestamp, and all human decisions/splits. Resources and old work context are covered conservatively by global evidence/revision. Missing durable revision disables caching without source schema writes. Computation runs inside the existing caller transaction or a temporary read transaction; writes go only to derived storage. A second signature check precedes cache publication. Admission observes configured storageLimitMB and 90% capture headroom. Optional bypassProjection supports equality checks without adding UI settings.

Validation: initial three new regressions failed against baseline (missing generic API, Review replayed raw projection, billing had no view table); after implementation all six new regressions pass. Focused combined run: 52 tests pass across persistent-reading-views, home-day-cache, persistent-periods, billing-service, period-report-performance. Typecheck passes. Tests cover restarts, pinned snapshots with concurrent late evidence, external delete, settings/chunk bounds, counter expiry and clock rollback, corruption, budget/admission/discard, legacy no-revision and unsafe read bypass. All fixtures are temporary synthetic databases; no user database was opened.
