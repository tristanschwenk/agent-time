# Agent Time 0.2.0-beta.59

History preparation now shows its progress and completion so you can see when reports can use already calculated periods.

This version corrects eleven storage and data-management issues. Archive import, restore and compression protect committed SQLite journal data and concurrent writes. Export, compression and import recover their own interrupted temporary files safely. Storage usage includes billing exports, explains the actual pause reason, and reports older unverified temporary files without deleting them. An explicit manual stop cancels storage auto-resume.

Historical preparation discovers corrected event dates and all valid rowids, resumes date registration in bounded batches and avoids repeating unchanged work. Review backlog follows resource expiry correctly. Usage polling indexes hook events to avoid repeatedly scanning foreground-only history.

Original proof events, manual decisions, saved reports and timing/billing formulas are preserved. The derived-history schema upgrade may trigger a one-time background rebuild; reports retain the existing calculation fallback. Plain SQLite archives with active journals are refused so committed evidence is not silently omitted.

On synthetic paired fixtures, idle date registration fell from roughly 1.07 seconds to 9 milliseconds; complete date registration fell from 8.2 to 1.7 seconds across bounded batches. Warm hook polling fell from 6–7 milliseconds to about 0.04 milliseconds. These isolate redundant background operations, not total report latency. Registration peak memory increased slightly from 133 to 136 MiB in the measured run; no RAM reduction is claimed.

Validation: 830 JavaScript tests, 38 native tests, production build/typecheck, packaged helper smoke and independent reviews.
